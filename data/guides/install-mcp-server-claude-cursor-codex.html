The server is the same. The config is not.

An MCP server (Model Context Protocol) is a small program that exposes tools and data to an app like Claude Desktop, Cursor or Codex. The protocol is open, so one server can talk to all three. What changes is the wrapper: the file you edit, the field names, and whether you paste JSON, TOML, or a CLI command.

There are two common shapes:

  • Local (stdio). The app starts a command on your machine, such as npx, uvx or a binary, and talks to it over stdin and stdout. This is the format official MCP docs use for the filesystem server, and the one most GitHub READMEs show as a command plus args.
  • Remote (Streamable HTTP or SSE). You give the app a URL. The server runs somewhere else. Some need an API key in a header, some use OAuth in the browser, some (like our own catalog server) need no login at all.

If you already have a working JSON block for Claude or Cursor and you just need it in Codex TOML, skip the typing and use our free MCP config converter. It runs in your browser. This guide is the longer version: where each file lives, how to add a server in the UI, and how to read the install lines you see on PickAPlugin listings.

A gotcha: claude mcp add is Claude Code, not Claude Desktop

A lot of READMEs, and a lot of listings in our catalog, start with claude mcp add. That command is from Claude Code's MCP docs. It writes Claude Code's config. It does not, by itself, add the server to the Claude Desktop app.

The good news is the ingredients are usually the same. A line like:

claude mcp add ztd-charts -- npx -y ztd-charts-mcp

means: start a local server with command npx and args -y, ztd-charts-mcp. You can drop those into Claude Desktop's JSON, Cursor's mcp.json, or Codex's codex mcp add as shown below. That's the install line from ztd charts.

A line with --transport http and a URL is a remote server. Starpop MCP lists both:

claude mcp add --scope user --transport http starpop https://starpop.ai/api/mcp
codex mcp add starpop --url https://starpop.ai/api/mcp

Same endpoint, two clients. Cursor just wants that URL in mcp.json.

Claude Desktop

Anthropic now steers most people toward desktop extensions, which are one-click packages for local MCP servers. The older JSON file is still officially documented and is what you'll use when a project only gives you a command and args.

Option A: install from the official extensions directory

Per Anthropic's Claude Desktop help article:

  1. Open Settings → Desktop app and click Manage next to Extensions. (Older layouts put this under Settings → Extensions.)
  2. Click Browse extensions, pick a tool Anthropic has reviewed, and click Install.
  3. Fill in any required settings, such as an API key, in the form Claude shows you.
  4. The extension should then be available in your conversations.

Extensions from that official directory update automatically by default. That is the low-friction route when the server you want is in the directory.

Option B: install a custom .mcpb file

If a developer gave you a desktop extension package, the same help article says: open the Extensions manager, click Advanced settings, find the Extension Developer section, click Install Extension…, and choose the .mcpb file. Claude Desktop includes a built-in Node.js environment, so a Node-based extension does not require you to install Node yourself.

Option C: edit claude_desktop_config.json

This is the method in the official MCP guide Connect to local MCP servers. In Claude Desktop, open Settings from the Claude menu in the system menu bar (not the in-window account settings), go to the Developer tab, and click Edit Config. That opens or creates:

  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%\Claude\claude_desktop_config.json
  • Linux: ~/.config/Claude/claude_desktop_config.json

A local stdio server looks like this (the filesystem example from those official docs, with paths you must change):

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/username/Desktop",
        "/Users/username/Downloads"
      ]
    }
  }
}

On Windows the same idea uses paths like C:\\Users\\username\\Desktop. Official docs are clear on two points that trip people up: use absolute paths, not ./something, and fully quit Claude Desktop and reopen it after you save. Closing the window is not always enough.

The filesystem server can read and change any directory you list, with the same permissions as your user account. Only grant folders you're comfortable with an agent touching. There's a longer checklist for that in how to check if an MCP server is safe before installing.

Need an API key? Official debugging docs put it in an env object on that server:

{
  "mcpServers": {
    "myserver": {
      "command": "npx",
      "args": ["-y", "some-mcp-package"],
      "env": {
        "API_KEY": "your-key"
      }
    }
  }
}

Don't commit that file if it has secrets. Prefer a key that can be revoked.

Remote servers in Claude Desktop

For a hosted URL, current Claude Desktop builds can add a custom connector: Settings → Connectors → Add custom connector, then paste the URL. That's how we tell people to add the PickAPlugin MCP server at https://pickaplugin.com/mcp (Streamable HTTP, no auth).

On older Desktop versions that don't offer custom connectors, a common workaround is to run the official mcp-remote helper as a local command that points at the URL:

{
  "mcpServers": {
    "pickaplugin": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://pickaplugin.com/mcp"]
    }
  }
}

That still needs Node, because it uses npx.

Did it connect?

Anthropic's help article says to click the + button at the bottom of the chat box, then Connectors, to see connected MCP servers and their tools. You can also check the Local MCP servers section on the Extensions page, or Settings → Developer on older layouts, and read the logs if a server is red.

If a server doesn't show up: fully restart Claude Desktop, validate the JSON (a missing comma will silently break the file), confirm any paths are absolute and exist, and if the command is npx, confirm Node.js is installed and on the PATH that the Desktop app sees.

Cursor

Cursor's own docs are at cursor.com/docs/mcp, with a shorter walkthrough in the MCP help page. Cursor supports local stdio servers and remote servers over Streamable HTTP or SSE, plus OAuth when the server asks for it.

One-click install

  1. Open Customize in the sidebar and click MCPs.
  2. Browse or search, then click Add to Cursor.
  3. Finish any sign-in prompts if the server uses OAuth.

Official and team-distributed servers also show up there. Cursor's docs point at the Cursor Marketplace for official plugins, and at cursor.directory for community servers.

Manual install with mcp.json

Create a file in one of these places (both are officially supported, and they're merged):

  • All your projects: ~/.cursor/mcp.json
  • Just this repo, safe to share if it has no secrets: .cursor/mcp.json in the project folder

If the same server name appears in both, the project file wins.

Local Node server, from Cursor's docs:

{
  "mcpServers": {
    "server-name": {
      "command": "npx",
      "args": ["-y", "mcp-server"],
      "env": {
        "API_KEY": "value"
      }
    }
  }
}

Remote server:

{
  "mcpServers": {
    "pickaplugin": {
      "url": "https://pickaplugin.com/mcp"
    }
  }
}

If the remote server needs a static header, Cursor's help page puts it under headers:

{
  "mcpServers": {
    "ipgeolocation": {
      "url": "https://mcp.ipgeolocation.io/mcp",
      "headers": {
        "X-IPGeolocation-API-Key": "your-key"
      }
    }
  }
}

That URL and header name come from the IPGeolocation.io MCP Server listing (a free or paid API key is required, and their plan limits still apply). Don't commit the key. After you save the file, restart Cursor.

We also have an Add to Cursor button on the PickAPlugin MCP page if you just want the catalog in Agent.

Using tools, and logs

Cursor's help page says Agent picks MCP tools up automatically when they're relevant. You can toggle a tool in the tools list at the top of the chat panel. By default, Agent asks before it runs an MCP tool. In Cursor 3.6 and above, Auto-review mode (Settings → Agents → Approvals & Execution) can let allowlisted tools run immediately and send the rest through a safety classifier. Keep an eye on that if you'd rather approve each call yourself.

If a server won't start: open the Output panel (Cmd+Shift+U on macOS, Ctrl+Shift+U on Windows or Linux), choose MCP Logs, and look for a bad path, a missing env var, or a crash. You can also toggle a server off and on under Customize → MCPs without deleting it. Cursor's docs note that servers started from the GUI don't always inherit environment variables from your shell profile, so put secrets in the env block (or Cursor's own env settings) rather than assuming export in ~/.zshrc is enough.

Codex (CLI, IDE and ChatGPT desktop)

OpenAI's current walkthrough is Model Context Protocol on ChatGPT Learn. Codex stores MCP config in TOML, not JSON. The default file is ~/.codex/config.toml. You can also use a project-scoped .codex/config.toml, but only in trusted projects. The ChatGPT desktop app, the Codex CLI and the IDE extension share this config, so you set a server up once.

ChatGPT in the browser is a different path: it does not read your local config.toml. Remote MCP tools there go through plugins. This section is for the local Codex host (desktop app, CLI and IDE).

In the ChatGPT desktop app or the IDE extension

  1. Open Settings, then MCP servers (in the IDE, that's the gear menu, then MCP servers).
  2. Click Add server.
  3. Give it a name, choose STDIO or Streamable HTTP, and paste the command or the URL.
  4. Save, then click Restart (or Restart extension in the IDE).

The list shows which servers are enabled and which need OAuth. Use Authenticate when a server asks you to sign in. In the composer, type /mcp to see connected servers. In the Codex terminal UI the same command works.

With the CLI

Official pattern for a local server:

codex mcp add <server-name> --env VAR1=VALUE1 -- <stdio server-command>

OpenAI's own example is Context7:

codex mcp add context7 -- npx -y @upstash/context7-mcp

For a remote URL:

codex mcp add pickaplugin --url https://pickaplugin.com/mcp
codex mcp add starpop --url https://starpop.ai/api/mcp
codex mcp add taisly --url https://app.taisly.com/mcp

The Starpop line is from the Starpop listing. The Taisly line is from Taisly Agent Kit. Then run codex mcp list to confirm. For a server that uses OAuth, run codex mcp login SERVERNAME. If you don't have a browser in that terminal, codex mcp login --no-browser prints a URL; after you sign in, paste the full redirect URL back into the terminal.

IPGeolocation.io also publishes a local Codex install that passes the key as an env var instead of a header:

codex mcp add ipgeolocation --env "IPGEOLOCATION_API_KEY=$IPGEOLOCATION_API_KEY" -- npx -y ipgeolocation-io-mcp@latest

Their listing says the local package wants Node.js 22 or later. @latest always pulls the newest package. If you'd rather pin a version, see the safety guide.

By hand in config.toml

Each server gets a [mcp_servers.NAME] table. Local:

[mcp_servers.context7]
command = "npx"
args = ["-y", "@upstash/context7-mcp"]

Remote:

[mcp_servers.pickaplugin]
url = "https://pickaplugin.com/mcp"

Official options worth knowing, from the same Codex docs: env sets environment variables, cwd sets the working directory, startup_timeout_sec defaults to 10, tool_timeout_sec defaults to 60, and enabled = false turns a server off without deleting it. You can also set enabled_tools or disabled_tools if you only want some of a server's tools.

For a remote server that needs a bearer token, prefer bearer_token_env_var = "MY_TOKEN" so the token isn't sitting in the file. Static headers go in http_headers. Headers that should be read from the environment go in env_http_headers. That's also what our converter emits when you paste a JSON headers block and ask for Codex TOML.

One server, three configs (a worked example)

Take a local install like the one on ztd charts: npx -y ztd-charts-mcp.

{
  "mcpServers": {
    "ztd-charts": {
      "command": "npx",
      "args": ["-y", "ztd-charts-mcp"]
    }
  }
}
[mcp_servers.ztd-charts]
command = "npx"
args = ["-y", "ztd-charts-mcp"]

The JSON on the left goes in Claude Desktop's claude_desktop_config.json, or in Cursor's mcp.json. The TOML on the right goes in ~/.codex/config.toml. Or skip the TOML and run codex mcp add ztd-charts -- npx -y ztd-charts-mcp.

Another local example from the catalog: Solar Icons lists npx -y @solar-icons/mcp. Same pattern, package name @solar-icons/mcp. Their listing says it reads a local icon catalog and doesn't need an API key, which is a nicer setup to practice on than a server that wants production credentials.

A remote example you can try without a key is our catalog:

claude mcp add --transport http pickaplugin https://pickaplugin.com/mcp
codex mcp add pickaplugin --url https://pickaplugin.com/mcp

In Cursor, use the JSON url block above, or the Add to Cursor button on the MCP server page. It's read-only search: names, descriptions, categories and install commands for the plugins and MCP servers we list. We don't audit what those projects do, so still read a listing before you install the thing it pointed you at.

How to read a PickAPlugin listing

Open any catalog page and look at the install box. We copy that text from the project's README (or from what the maker sent us). It is not a command we invented, and it may be written for only one client.

  • If it starts with claude mcp add, it's a Claude Code line. Translate the command or URL into Desktop / Cursor / Codex as shown above.
  • If it starts with codex mcp add, you can run it in the Codex CLI as written, then reuse the same command or URL in the other apps.
  • If it's just npx … or uvx …, wrap it as command plus args.
  • If it's a bare https://… URL, that's a remote server. Check the listing for the header or OAuth notes.
  • If it says codex plugin marketplace add or claude plugin marketplace add, that's a plugin, not a raw MCP config. Use how to install a Codex plugin instead. Some plugins bundle an MCP server, and the plugin install sets that up for you.

Each listing also shows the last GitHub update (when we have a repo), whether it's archived, the license, and the install line. That's useful context, not a safety rating. For the actual pre-install checks, use the MCP safety guide.

Want to browse from the agent itself? Add the PickAPlugin MCP server, then ask it to search the catalog. If you built a server and want it listed, submit it free, and see every other place to submit an MCP server.

Quick troubleshooting

  • Nothing shows up after you edit a file. Restart the app for real. Claude Desktop in particular wants a full quit. Cursor wants a restart after mcp.json changes. Codex wants Restart on the MCP servers page, or a new CLI session after codex mcp add.
  • JSON or TOML won't parse. A trailing comma in JSON, or a typo in a table name like [mcp_servers.my server] without quotes, will do it. Paste the file into a validator, or use our converter and copy the result back.
  • npx or uvx not found. The Desktop or GUI app may not see the PATH from your terminal. Use the full path to the binary (which npx or where npx).
  • Works in the terminal, fails in the app. Official MCP debugging docs note that stdio servers often start with a sparse environment and a working directory that isn't your project (on macOS it can even be /). That's why absolute paths and explicit env blocks matter.
  • Remote server asks you to log in. That's normal for OAuth. In Codex run codex mcp login. In Cursor and Claude, use the Authenticate or connector prompt the app shows you.
  • The tool list is empty. The process may have crashed on startup (bad path, missing key, Node version). Read the app's MCP logs before you rewrite the config.

Still stuck on a format conversion only? Convert the config and compare it with the examples here. And before you point a new server at a real repo, mail account or production database, spend a few minutes on the safety checklist.
